# Ревью Home

Дата: 17 октября 2026 года. Проверены весь Kotlin-код приложения, тесты, manifest, ресурсы, Gradle, скрипты сборки и CI. Исправления находятся в рабочей копии.

## Что исправлено

| Приоритет | Проблема | Результат |
| --- | --- | --- |
| P1 | Неполный кэш или временно недоступный профиль удалял закрепления. | Отсутствующие приложения временно скрываются. Их закрепления, группы и порядок сохраняются при правках видимых приложений. |
| P1 | Fallback запуска рабочего приложения мог открыть личную копию того же компонента. | Обычный Intent разрешён только для текущего пользователя. Неизвестный профиль из дискового кэша пропускается. |
| P1 | Исключение при чтении одного профиля отбрасывало приложения остальных. | Профили загружаются независимо; fallback текущего профиля сохраняет его настоящий serial. |
| P1 | Смена запроса во время drag могла сохранить результаты поиска как закрепления. | Смена запроса отменяет drag. Перед сохранением проверяется исходный состав списка; Activity также блокирует операции перестановки в поиске. |
| P1 | Отмена анимации выполняла изменение из `finally`; исключение callback могло повторить его. | Отмена очищает состояние без изменения порядка. Callback сохранения вызывается один раз. |
| P2 | Геометрия drag использовала номер среди видимых строк вместо индекса модели. | Hit-test и координаты завершения используют абсолютные индексы, включая частично видимый список. |
| P2 | Другой палец или системный CANCEL мог завершить чужой drag. | Обрабатывается исходный pointer ID; отмена, уничтожение UI и уже закрытый coroutine scope очищают overlay. |
| P2 | Проверки ёмкости групп в UI и менеджере расходились. | Hover и сохранение используют один predicate с учётом скрытых участников. При извлечении скрытые участники остаются в исходной группе. |
| P2 | Миграция старых ID могла закрепить одноимённое приложение другого профиля. | Старый компонент сопоставляется только текущему пользователю. Учтён прежний fallback для вторичного пользователя и совпавшие дубли. |
| P2 | Кэш иконок не очищал память, затрагивал соседние пакеты и мог восстанавливать устаревший результат после invalidation. | Инвалидация совпадает с точным пакетом и отменяет ожидающие результаты. Имена файлов не смешивают `_` и `$`. |
| P2 | Каждое обновление заранее декодировало все иконки и удерживало их вне LRU. | Репозиторий загружает метаданные. Иконки загружаются по требованию, повторные запросы объединяются; PNG рисуется и сжимается вне блокировки. |
| P2 | Равенство `App` без drawable мешало заменить снимок при обновлении одной иконки. | State списка заменяет снимок по ссылке; иконки получают актуальный источник. |
| P2 | Пустой список не заменял старый кэш; предварительная проверка файла мешала восстановлению AtomicFile. | Пустой снимок сохраняется, чтение использует механизм восстановления AtomicFile. |
| P2 | Повреждённый элемент закреплений обнулял всю запись; дубли могли создавать одинаковые Compose keys. | Некорректные элементы пропускаются, пустые и повторные ID удаляются при чтении и записи. |
| P2 | Программная прокрутка учитывалась как жест уведомлений. | Учитывается только пользовательская прокрутка. |
| P2 | Скрипты повторно выбирали JDK и ломались при запуске из `scripts/`; release без аргументов подменял версию на `1.0.0/1`. | JDK выбирается только в `gradlew`. Release использует версии проекта по умолчанию; переданные версии валидируются. |

## Упрощение и унификация

- Операции над закреплениями сохраняют порядок через общий путь. Удалены дублирующие неиспользуемые методы и внешний вызов `saveOrder` из Activity.
- Отложенное обновление после drag применяет уже загруженный снимок вместо повторного запроса.
- Строка приложения и drag overlay используют один `AppRowContent`.
- Удалены устаревшие алгоритмы hit-test, функция без действия `packedRowBounds`, дубли состояния активности drag, лишние поля и логирование каждого движения.
- Поиск нормализует запрос один раз, использует общий лимит длины и стабильную сортировку независимо от системной локали. Расчёт расстояния пропускает заведомо неподходящие слова.
- Удалены неиспользуемые ресурсы; исправлены замечания Compose к чтению ресурсов и примитивному state.

## Проверка

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug testReleaseUnitTest lintRelease assembleRelease
shellcheck scripts/*.sh .githooks/pre-commit
git diff --check
```

Итог: debug и release проходят по **94 теста**, без пропусков и ошибок. Обе сборки APK собраны, lint завершился без ошибок, ShellCheck и проверка diff прошли. Число тестов выросло с 41 до 94; Kotlin-код приложения сократился с 3196 до 3079 строк, UI — с 2026 до 1845. Проверен запуск `build.sh` непосредственно из каталога `scripts/`.

На Samsung SM-F741B / Android 16 через ADB проверены поиск и запуск приложения, закрепление и открепление, перестановка строки, извлечение из группы, возврат в нужную группу и слот, ACTION_CANCEL, изменение запроса во время drag и открытие уведомлений. Исходные закрепления и их порядок восстановлены.

На эмуляторе Android 11 проверены запуск, перестановка с невидимыми начальными строками списка, поиск с опечаткой и запуск лучшего результата через Enter. Эмулятор запущен с `-read-only`; исходные тестовые закрепления восстановлены.

JVM-тесты дополнительно покрывают ошибки сервисов и профилей, миграции, скрытые закрепления, инвалидацию и гонки кэша, multi-touch, отмену coroutine scope и замену списка во время анимации. Переключение рабочих профилей на личном телефоне не выполнялось.

## Принятые ограничения

- Удалённое приложение сохраняет скрытое закрепление и возвращается на своё место после переустановки. По отсутствию приложения нельзя надёжно отличить удаление от временно недоступного профиля.
- Открытие уведомлений по-прежнему использует системный метод через reflection. На проверенном Samsung работает; поддержка зависит от прошивки.
- Lint оставляет два предупреждения: версия `activity-compose` и базовый adaptive icon без monochrome. Монохромная иконка уже определена отдельно для API 33+. Обновление зависимостей не включено в этот рефакторинг.
- Скриншоты, снимки настроек и временные ADB-сценарии находятся в игнорируемом `build/review-device/`; в исходники не включены.
